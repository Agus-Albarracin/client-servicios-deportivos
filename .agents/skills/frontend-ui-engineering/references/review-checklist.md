# UI Review Checklist

- The primary task and next action are immediately understandable.
- The implementation reuses the project’s visual language or creates a small reusable decision for a real gap.
- Realistic content does not break hierarchy, overflow, or action priority.
- Native semantics, labels, keyboard access, and visible focus are present.
- Relevant pending, empty, error, success, and recovery states are covered.
- The UI remains useful across supported viewport sizes and larger text.
- Relevant checks were run, or unavailable checks were reported plainly.
